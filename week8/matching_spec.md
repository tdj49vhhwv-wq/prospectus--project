# Week 8 事件级匹配规范（预注册）

**定稿日期**：2026-08-07
**适用**：8 家开发集 Auto-vs-Gold 事件级评价

---

## 1. 分析单位

事件级。Gold 与 Auto 各自先聚合为事件：

```text
事件 key = (stock_code, event_date, event_type_top_level)
```

- Gold 事件：从 `subscription_flow_gold.jsonl` 按 `(公司, 日期, 事件类型)` 聚合投资人明细；`share_transfer_flow_gold.jsonl` 每条转让明细即一条事件（类型 D）；
- Auto 事件：从 `week6/auto_output_md/*.jsonl` 按 `(公司, 日期, 事件类型)` 聚合候选行；同一事件的重复披露合并为一条事件。

## 2. 类型映射

| 事件上下文 | 顶层类型码 |
|------|------|
| 设立 | E |
| 增资 | A |
| 整体变更 | B |
| 增资及股权转让 / 增资+转让 | C |
| 股权转让 | D |
| 资本公积转增 | F |
| 吸收合并 | G |
| 员工持股平台出资 / 员工激励 | J |

子类（A:A1-A:A6、D:D1-D:D6）在事件级不区分，只比较顶层码。

## 3. 日期匹配

按 Gold 的粒度比较：

| Gold 粒度 | 匹配条件 |
|------|------|
| `day` | Auto 日期与 Gold 同日 |
| `month` | Auto 日期与 Gold 同年同月 |
| `year` | Auto 日期与 Gold 同年 |

Auto 缺日期的候选事件无法匹配任何 Gold，计入 FP。

## 4. 匹配算法

一对一贪心匹配，确定性执行：

1. Gold 按 `(公司, 日期, 类型)` 排序；
2. Auto 按 `(公司, 日期, 类型, 上下文)` 排序；
3. 逐条 Gold 取第一个满足“同公司 + 同顶层类型 + 日期兼容 + 尚未被占用”的 Auto，记为 TP；
4. 剩余 Gold → FN；剩余 Auto → FP；
5. 禁止一条 Auto 匹配多条 Gold，禁止一条 Gold 匹配多条 Auto。

## 5. 指标

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2 × Precision × Recall / (Precision + Recall)
```

必须报告：全样本、分公司、分事件类型；分母为零填 `N/A`，不填 100%。

## 6. 手工测试样例（12 个）

| # | 场景 | 预期 |
|---|------|------|
| 1 | day 精确命中 | TP |
| 2 | Gold `month`，Auto 带日 | TP（同年同月） |
| 3 | Gold `day`，Auto 同日不同上下文但同顶层类型 | TP |
| 4 | 同一事件重复披露两次 | Auto 合并为一条事件 |
| 5 | 复合事件 C 与单 A 或单 D | 不跨类型匹配 |
| 6 | 同公司同日不同类型 | 各匹配各的 |
| 7 | 多投资人明细合并 | 一条事件一条记录 |
| 8 | 股权转让单条明细 | 一条事件一条记录 |
| 9 | Auto 缺日期 | FP |
| 10 | 明显非投资人实体候选 | FP |
| 11 | 一对多 Auto 候选 | 只能匹配一次，其余 FP |
| 12 | 金额轻微误差（字段级） | 事件仍 TP，字段一致率单列 |

样例实现见 `tests/test_evaluate_events.py`（当前覆盖 1、2、3、4、5、7、8、9 的核心逻辑）。

## 7. 已知边界

- 本规范只评价事件是否被找到，不评价字段是否正确；
- 字段级一致率（金额、估值、轮次、日期）另作次要报告；
- 投资人明细级评价器（谁投、多少钱、多少股）为 Week 8 后续任务，不在本文件范围。
