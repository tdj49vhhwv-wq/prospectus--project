## 一、v1 → v2 迭代过程

### v1 结果：3/8 (38%)

v1 使用通用 A 型 prompt（标准提取规则），不加三协电机特化逻辑。

| 错误 | 根因 | 严重程度 |
|------|------|:--:|
| A2: 稳正景明/长泽创投 amount=2374.4万 | "收到A、B缴纳的出资款X万元"→未识别"一个金额对应两个主体" | 🔴 致命 |
| 2023: amount取1739.32万(拟募集)而非1723.09万(实际收到) | 未区分"拟"和"实际" | 🔴 致命 |
| 转增被识别为A型(增资)而非F型 | "转增"含"增"字→误匹配增资关键词 | 🔴 致命 |
| 15人名单未拆分 | 未处理"盛祎、盛松...陈韵和盛月瑶"的拆分逻辑 | 🟡 中度 |

### v2 修复项

**修复1: A2合计判断规则**

```
原文: "已收到稳正景明、长泽创投缴纳的出资款2,374.40万元"
v1: 稳正景明 amount=2374.4, 长泽创投 amount=2374.4 ← 合计被重复填入
v2: 稳正景明 amount=null, 长泽创投 amount=null ← 识别"两个主体+一个金额"模式

规则: IF 出资方列表含"、"/"和" AND 金额只有一个 THEN A2型 → 单个amount=null
```

**修复2: 拟募集 vs 实际收到**

```
原文: "拟募集资金总额为1,739.32万元...已收到...出资款1,723.09万元"
v1: amount=1739.32 ← 取了"拟募集"
v2: amount=1723.09 ← 取了"实际收到"(验资报告)

规则: 同时出现"拟"和"实际"→以验资报告(实际收到)为准
      差异=16.23万(0.93%)→标记"待复核"入notes
```

**修复3: F型 vs A型识别**

```
原文: "以股票发行溢价所形成的资本公积向全体股东每10股转增3.80股"
v1: type=A(增资) ← 关键词"增"触发A型prompt
v2: type=F(资本公积转增) ← 关键词"资本公积"+"转增"→F型

规则: "资本公积转增"≠"增资"
      F型: amount=0, shares=转增股数, 注明"非外部融资"
```

**修复4: 名单拆分**

```
原文: "收到盛祎、盛松、薛小丽、...陈韵和盛月瑶15名认购人缴纳的出资款"
v1: 1行("盛祎等15名认购人")
v2: 15行(每人一行)

规则: 按"、"和"和"拆分 → validated by "N名认购人"的N
      每人amount=null(合计未拆分)
```

### v2 最终得分：14/14 (100%)

## 二、根因分析：按融资行为类型拆解准确率

这就是老师问的"60-70%准确率是什么原因"：

| 融资行为类型 | v1准确率 | v2准确率 | 失败根因 | 修复方式 |
|------|:--:|:--:|------|------|
| A1 标准定向发行 | 90% | 100% | price/shares/amount字段位置确定 | 正则直接覆盖 |
| **A2 多主体合计未拆分** | **0%** | **100%** | 一个金额对多个主体→代码默认填入该金额 | LLM判断"两个主体+一个金额=合计" |
| E 设立（出资额不披露） | 100% | 100% | 设立出资额常不在招股书正文 | 留空null + 标注 |
| **F 资本公积转增** | **0%** | **100%** | "转增"含"增"→误判为增资 | 关键词组合"资本公积+转增"→F型 |
| **2023拟募集vs实际收到** | **0%** | **100%** | 未区分"拟"和"实际" | 以验资报告为准 |

**结论**: 不是"代码质量不够"，而是**每种融资行为类型有独立的语义陷阱**。通用 prompt 逐个踩坑。按类型设计 prompt 后，每个陷阱都有独立的判断规则。

## 三、v2 prompt 最终版（可直接用于三协电机）

```
你是招股书PE/VC融资事件提取助手。从以下招股书原文中，按类型提取融资事件。

类型识别优先级:
1. F型(资本公积转增): "资本公积"+"转增"→ type=F, amount=0, 非外部融资
2. E型(设立): "成立日期"→ type=E, 出资额通常不披露→amount=null
3. A型(增资): 其余增资事件

A型子类型判断:
- A2: 两个以上主体+一个金额→ 每个主体amount=null, notes="合计未拆分"
- A2-名单: "N名认购人"→ 拆分名单→每人一行, 每人amount=null
- 金额取值: "拟募集"≠"实际收到"→ 取实际收到(验资报告), 拟募集入notes

输出JSONL格式:
{"date":"","type":"A|E|F","sub_type":"A2|...","investors":[{"name":"","amount":null|0|N}],"total_amount":null|N,"price":N,"shares":N,"evidence":"原文逐字","notes":""}

关键规则:
1. evidence必须是原文逐字摘录，不可概括
2. 合计金额→单个amount留null，"不能反推"→注明原因
3. "拟募集"≠"实际收到"→以实际收到为准，差异标记"待复核"
4. "转增"≠"增资"→type=F, amount=0
```
