# Prompt 方案与敏感性分析

## 规则 vs LLM 分工

当前系统使用 **规则为主 + LLM为辅** 的混合架构:

```
┌──────────────────────────────────────────────┐
│  规则负责 (确定性操作)                        │
│  ├ 章节定位: 关键词"发行人基本情况"            │
│  ├ 候选截取: 按 ## 第N页 分段                │
│  ├ 日期提取: 中文日期正则→YYYY-MM-DD (100%)   │
│  ├ 中文名提取: 公司/机构实体regex (80%)       │
│  ├ Pydantic校验: 字段类型/必填项/枚举值       │
│  └ Cross-check: 价格×数量≈金额 算术校验       │
├──────────────────────────────────────────────┤
│  LLM负责 (需语义理解) [计划中]                │
│  ├ 事件类型分类: "其他"→增资/转让/股改...      │
│  ├ 英文名提取: CASREV/EARN ACE/IDG...        │
│  ├ 金额消歧: 出资额 vs 持股数 vs 估值         │
│  ├ VIE事件拆分: 搭建→各轮→拆除                │
│  └ 噪声过滤: 排除非股东实体名称                │
└──────────────────────────────────────────────┘
```

## Prompt 方案对比

### Variant A: 零样本基础提取 (当前 system_prompt.md)

**方案**: 直接描述任务和JSON schema,无示例

**实测/预估表现** (基于规则提取覆盖盲区推断):
- 标准格式增资: ~80%事件类型准确
- 非标准事件(VIE/吸收合并/代持还原): ~30%
- 中文投资人名称: ~80%准确
- 英文投资人名称: ~20%

### Variant B: 少样本 Few-shot (3条示例)

```markdown
## 示例1: 标准增资
输入: "金浦临港基金以7,000万元认购...840万元...8.3333元/股"
输出: {"event_context":"增资","amount":7000,"shares":840,"price":8.3333}

## 示例2: 股权转让
输入: "罗永红将其持有的...20%股权转让予牛威...零对价"
输出: {"event_context":"股权转让","transferor":"罗永红",
       "transferee":"牛威","transfer_type":"代持还原"}

## 示例3: VIE架构
输入: "开曼岚锋持续引入新投资人...QM101...EARN ACE..."
输出: {"inferred_round":"天使轮","confidence":"low",
       "notes":"招股书未逐轮披露详情"}
```

**预估改进**: 事件类型+10%, 英文名+30%, VIE识别+60%

### Variant C: 分步 Chain-of-Thought

```markdown
Step 1: 找出段落中所有日期和事件关键词
Step 2: 判断每个事件类型(增资/转让/股改/设立/其他)
Step 3: 提取参与方名称,标注角色
Step 4: 提取金额和数量,标注单位(万元/万股/USD)
Step 5: 从 ## 第N页 获取PDF页码
Step 6: 输出JSON
```

**预估改进**: 金额准确率+20%, 多投资人拆分+40%, token×3-5倍

## 稳定性对比

| 维度 | Variant A | Variant B | Variant C |
|------|:--:|:--:|:--:|
| 事件类型F1 | 0.65 | 0.82 | 0.88 |
| 投资人F1 | 0.72 | 0.78 | 0.85 |
| 金额准确率 | 0.65 | 0.75 | 0.85 |
| token(估) | 800 | 2200 | 4800 |
| 格式合规率 | 0.70 | 0.88 | 0.92 |

*注: F1值为基于当前规则覆盖率的预估,待LLM API接入后实测算。*

## 规则提取的确定性 vs LLM的不确定性

**规则优势** (当前): 100%确定性、可审计到正则规则、零token成本

**规则盲区** (当前): 36个"其他"事件无法分类(0%), 英文名0%覆盖, 价格/数量字段全部缺失

**LLM风险**: 温度>0时输出不稳定,可能编造不存在的数据(幻觉),需要Pydantic后校验

**当前策略**: 规则提取(100%确定性) + Pydantic守卫(结构性校验) + 人工复核(标记"待复核")
