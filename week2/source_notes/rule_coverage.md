## 五、哪些事件规则抽不到,必须LLM/人工

### 必须LLM(语义理解)

| 场景 | 影响数 | 规则为什么失败 |

## 七、规则 vs LLM vs 人工边界

```
规则 → 日期/中文名/金额 → 51% coverage, 100%确定性
  ↓
LLM → 事件分类/英文名/过滤噪声 → 计划提升到80%+
  ↓  
人工 → PDF不披露/VIE拆轮 → 必须人工
```

## 八、LLM使用说明

### 当前模式: LLM辅助 + 规则提取 + 人工复核

本项目实际使用了LLM，但不是以API调用的方式嵌入流水线：

| 环节 | 谁做的 | 怎么做的 |
|------|------|------|
| **人工Gold制作** | LLM辅助 | 我(Claude)读取PDF解析文本,逐事件提取结构化JSON,人确认 |
| **规则自动提取** | 纯规则 | `extract_with_rules.py` 正则匹配,不调API |
| **Schema校验** | Pydantic | 确定性校验,不调API |
| **Cross-check** | 算术规则 | price×shares≈amount,不调API |
| **Auto vs Gold对比** | 规则 | 逐字段diff,不调API |

### 为什么不把LLM嵌入流水线

- 规则提取覆盖51%事件,成本$0,100%确定性
- LLM API调用的稳定性/幻觉风险需要Pydantic后校验
- 当前流水线已形成闭环: LLM做Gold → 规则做Auto → 对比差异 → 人工复核
