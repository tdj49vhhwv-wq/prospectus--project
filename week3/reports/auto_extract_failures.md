# 自动提取系统性失败模式分析

生成时间: 2026-06-16

## 模式1: VIE/红筹架构 — 融资事件分散

**影响公司**: 影石创新 (688775)

**问题**: 红筹/VIE架构公司的融资历史分散在"VIE搭建"和"VIE拆除"两个段落中，
不在统一的"股本演变"或"历史沿革"章节。自动提取的正则匹配 `发行人基本情况` →
`股本演变` → `历次增资` 路径完全失效。

**表现**: 
- 6轮增资被合并为1个event (VIE搭建)
- 8家投资人被放入同一event
- 各轮次日期、金额、估值全部缺失

**现有处理**: 
- 手动拆分为4个独立事件(天使轮/A轮/B轮/C轮)
- 所有拆分事件标记为 confidence=low
- 日期按投资人类型推估

**建议**: 
- 对红筹公司单独建立"搭建→拆除"事件提取路径
- 扩展关键词: "VIE架构"/"红筹架构"/"协议控制"/"WFOE"/"镜像回归"
- 查验证监会问询回复文件补充各轮详情

## 模式2: 多轮合并 — "N次增资扩股"不逐轮披露

**影响公司**: 影石创新 (688775)

**问题**: 招股书验资报告中仅汇总提及"有限公司设立及六次增资扩股"，
不逐轮披露每次增资的日期、投资方、金额、估值。

**表现**:
- 单次验资报告(容诚验字[2020]518Z0004号)覆盖全部6轮
- 无法从文本中分离各轮次

**现有处理**: 
- 基于投资人类型(天使→VC→战略→PE)推估各轮
- 各轮金额、估值留空
- 明确标注"待查证监会问询回复"

**建议**: 
- 这是招股书本身的披露局限，非提取方法问题
- 需补充数据源: 证监会问询回复 / 工商变更记录 / 第三方数据库(企查查/天眼查)

## 模式3: 投资人名称消歧

**影响公司**: 友升股份 (603418), 三协电机 (920100)

**问题**: 
- 自动提取regex匹配实体名称(如 `{2,30}(有限(责任)?公司|合伙|企业|基金)` ),
  但实际投资人名称包含更复杂的实体结构。
- 同一投资人在不同段落使用不同名称(全称vs简称)
- "盛祎等15名自然人"这种聚合式表达无法自动拆分

**现有处理**:
- 手动从原文中提取完整法律实体名称
- 使用 `investor_original_name` 保存全称，`investor_short_name` 保存简称

**建议**:
- 建立投资人名称标准化映射表
- 对聚合式投资人("等N名")标记为 confidence=low
- 考虑使用LLM辅助名称消歧

## 模式4: MD行号作为source引用

**影响公司**: 全部8家 (Week 2初期)

**问题**: 
- 自动提取和手动提取最初都使用MD文件行号作为source_page引用
- 例如: "三联锻造3.md 第411-425行"、"黄山谷捷2.md 第590-602行"
- MD行号无法直接对应PDF页码，破坏证据回源链

**现有处理**:
- 创建 md_to_pdf_page.py 工具解析PyMuPDF输出的 `## 第N页` 标记
- 全部200+条记录的source_page已转为PDF页码格式
- 友升股份因使用MinerU输出(无 `## 第N页` 标记)，通过已有JSON中的PDF页码标注转换

**建议**:
- 新提取一律从PDF页码开始，不经过MD行号中间层
- 优先使用PyMuPDF输出(带 `## 第N页` 标记)而非MinerU(不带页码标记)

## 模式5: 缺乏t0股权结构快照

**影响公司**: 三协电机 (920100), 星图测控 (920116)

**问题**:
- 三协电机: 设立时(t0)的出资结构未明确披露(仅提及盛祎持股62.97%,朱绶青19.49%)
- 星图测控: t0出资结构有，但中间时点缺乏(2017年代持还原到2024年IPO前之间无快照)
- 导致逐股东cross-check无法执行

**现有处理**:
- 有t0数据的部分做cross-check
- 缺失部分在cross_check_summary中标记为空
- 日志中注明"缺少完整t0快照"

**建议**:
- 三协电机需从工商登记资料补充t0出资结构
- 星图测控需补充2017-2024年间的增资/股权转让事件
