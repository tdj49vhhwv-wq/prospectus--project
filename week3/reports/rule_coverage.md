# Rule Coverage Report — 规则提取覆盖范围

生成时间: 2026-06-17

## 1. 规则方法概述

**提取方法**: 纯正则表达式 + 关键词定位，不使用LLM。

**规则分工**:
- 章节定位 (locate_sections.py): 关键词匹配定位"发行人基本情况"→"股本演变"
- 候选提取 (extract_candidates.py): 按关键词截取上下文窗口
- 事件提取 (extract_with_rules.py): 正则匹配事件类型、提取投资人、金额、日期
- Schema校验 (validate_schema.py): Pydantic校验字段类型/必填项/枚举值
- 数值校验 (validate_schema.py): cross-check流量vs存量、价格×数量≈金额
- Gold对比 (compare_to_gold.py): 逐字段diff自动结果vs人工Gold

## 3. 系统性失败模式

### 模式1: 非标准事件类型 (0%覆盖)
- "增资及股权转让"组合事件: 规则只匹配单一类型
- "其他": 股改、吸收合并、VIE搭建/拆除等
- **建议**: LLM补充,规则负责提取日期和实体,LLM分类事件类型

### 模式2: 英文/混合语言投资人名称 (17%覆盖)
- CASREV FUND, EARN ACE LIMITED, QM101 Limited等
- 正则只匹配中文字符,英文名完全遗漏
- **建议**: 扩展正则匹配`[A-Z][A-Za-z\s]+(Limited\|Ltd\|FUND\|LP\|LLC)`

### 模式3: MinerU vs PyMuPDF输出格式差异 (友升0 snapshot)
- MinerU输出无`## 第N页`标记
- HTML格式表格解析逻辑不同
- **建议**: 统一使用PyMuPDF解析;或为MinerU单独写解析器

### 模式4: Auto ES精度低 (434 vs 83 gold)
- 正则匹配所有含"X%"的实体名称
- 大量噪声: 法人代表、注册资本、非股东机构
- **建议**: LLM过滤噪声;规则只负责候选提取

### 模式5: 金额/数量字段缺失 (35%缺少amount, 100%缺少shares/price)
- 金额正则只匹配"万"单位
- 数量需要区分"出资额(万元)"和"持股数(万股)"
- **建议**: LLM+单位上下文区分

## 4. 规则 vs LLM 分工建议

| 环节 | 当前方法 | 建议方法 | 理由 |
|------|------|------|------|
| 章节定位 | 规则(关键词) | **规则** | 关键词匹配精准,LLM过度消耗 |
| 候选文本截取 | 规则(上下文窗口) | **规则** | 确定性操作,无需推理 |
| 事件类型分类 | 规则(正则) | **LLM** | 36个"其他"事件需语义理解 |
| 投资人名称提取 | 规则(中文regex) | **规则+LLM** | 规则提取中文名(80%准确),LLM补充英文/消歧 |
| 金额/数量提取 | 规则(单位regex) | **LLM** | 需区分出资额/持股数/币种 |
| Schema校验 | Pydantic | **Pydantic** | 确定性校验,不需要LLM |
| 数值cross-check | 算术校验 | **规则** | 价格×数量≈金额纯算术 |
| Gold对比 | 记录对齐+diff | **规则** | 逐字段字符串比较 |
