# Prompt v3 — 全类型 × 分模块调用

**版本**: v3（基于 v1→v2 迭代 + 8家公司验证）
**设计原则**: Temperature=0.0 最大确定性 / 分类型小模块调用 优于 大模型一次提取
**覆盖**: 10种融资行为类型 (A/B/C/D/E/F/G/H/I/J)

---

## 调用架构

```
招股书原文 (10-20页 PE/VC章节)
  ↓
模块1: 增资提取 (A型) → 35+ 事件
模块2: 股权转让提取 (D型) → 20+ 事件
模块3: 结构性事件提取 (B/E/F/G/I/J型) → 30+ 事件
模块4: VIE提取 (H型, 仅影石触发) → 9 子事件
  ↓
合并 + 去重 + 关联校验
```

---

## 模块1: A型 — 增资事件提取

```
你是招股书增资事件提取助手。从以下原文中提取所有增资事件。Temperature=0.0。

输出每行一个JSON:
{"date":"YYYY-MM-DD","type":"A","subtype":"A1|A2|A3|A4|A5|A6","investor":"名称","investor_type":"PE|VC|政府基金|产业资本|外资|券商直投|员工平台|自然人","amount":null|数值,"shares":null|数值,"price":数值,"post_valuation":null|数值,"evidence":"原文逐字≤200字","data_source":"pdf_disclosed|calculated|inferred","notes":"判断依据"}

⚠️ 容易误判的三个陷阱 — 必须遵守:

1. A2合计未拆分
   ❌ "已收到稳正景明、长泽创投缴纳的出资款2,374.40万元" → 不要把2374.4填给每个人
   ✅ 两个以上主体+一个金额 → amount=null, notes="PDF只披露合计,未单独披露各自金额"

2. 拟募集≠实际收到
   ❌ 取"拟募集资金总额1,739.32万"
   ✅ 取"已收到...出资款1,723.09万"(验资报告金额)
   ✅ 差异>0.5% → notes="拟募集≠实际收到,差X万元(X%),以验资报告为准"

3. "转增"≠"增资"
   ❌ "资本公积转增" → 误判为增资
   ✅ "资本公积"+"转增" → 这是F型事件, 不在本模块处理

子类型判断:
- A1: price+shares+amount三字段完整 → 标准定向发行
- A2: "A、B缴纳X万元" → 合计未拆分
- A3: "员工持股平台"+"股份支付" → 员工激励增资
- A4: "投后估值约X亿" → 溢价有估值
- A5: "原股东同比例增资" → 非PE/VC
- A6: "持股比例保持不变"+"等比例" → 镜像回归增资(影石专用)

投资人类型:
- 名称含"创业投资/股权投资/创投/达晨/深创投..." → PE
- 名称含"天使/风险/IDG/启明/QM101/EARN ACE" → VC
- 名称含"政府引导/国有资本/供销社" → 政府引导基金
- 名称含"上市公司" 或 已知CVC列表 → 产业资本(CVC)
- 英文名+Ltd/LLC/Limited/Fund → 外资基金
- 名称含"员工/持股平台/合伙" → 员工持股平台
- 2-3个中文字符(非上述类型) → 自然人
```

## 模块2: D型 — 股权转让提取

```
提取原文中所有股权转让事件。Temperature=0.0。

输出每行JSON:
{"date":"YYYY-MM-DD","type":"D","subtype":"D1|D2|D3|D4|D5|D6","transferor":"转让方","transferee":"受让方","shares":null|数值,"amount":null|数值,"price":数值,"evidence":"原文逐字≤200字","notes":""}

子类型优先级(D1>D3>D2>D4>D5>D6):

D1 同一控制下转让:
  匹配: "同一股权结构"+"同一控制下" → 优先归类为D1
  示例: "本次股权转让系同一股权结构下的公司架构调整,转让价格为0元" → D1

D2 代持还原:
  匹配: "股权代持已解除""代持还原""还原代持"
  注意: 零对价, transferor_names和transferee_names可能为null(详情在外部文件)
  标记: traceability="external_required" (如果原文写"详见《公开转让说明书》")

D3 零对价转让:
  匹配: "转让价格为0元""未实际支付对价""零对价"
  注意: 只有NOT同时满足D1条件时才用D3

D4 外部转让:
  匹配: 新投资人通过受让老股进入 → 有明确对价(非0元)

D5 批量多对多:
  匹配: 同一时点3+转让方+3+受让方
  示例: 影石2019-11, CYZone/QM101/苏宁/岚烽→12+受让方, 统一价16.46元

D6 间接层面转让:
  匹配: 转让发生在股东层而非公司层
  示例: 友升2003-07, 第一美亚基金→陈桂荣(境外美国日升层面代持形成)

过滤规则:
- 排除子公司转让: evidence含"深圳三协/昆山谷捷/美国赛分"→跳过
- 排除非发行人本体: evidence前200字不含"发行人/公司股东/招股"→跳过
```

## 模块3: 结构性事件提取 (B/E/F/G/I/J)

```
提取以下六种结构性事件。每事件独立一行JSON。Temperature=0.0。

1. B型: 整体变更(股改)
   模式: "整体变更设立股份有限公司""净资产X元按Y:Z折为A万股"
   输出: {"date":"","type":"B","net_assets":数值,"conversion_ratio":"X:Y","post_shares":数值,"initiators":["发起人1"...],"evidence":""}

2. E型: 设立
   模式: "成立日期X年X月X日" 或 "X年X月,XXX设立XXX"
   规则: 如果设立出资额未披露 → amount=null, notes="招股书未披露设立出资额"

3. F型: 资本公积转增
   模式: "资本公积...每X股转增Y股" 或 "资本公积转增股本"
   ⚠️ 关键: amount=0 (非外部融资!), event_context="资本公积转增"
   规则: "资本公积"+"转增"组合词 → F型。单独的"转增"不确定→不提取

4. G型: 吸收合并
   模式: "吸收合并"+"同一股权结构"
   规则: 名称A吸收合并名称B, 注册资本X→Y
   仅黄山谷捷需要, 其他公司跳过

5. I型: IPO上市
   模式: "首次公开发行""发行X股×Y元""募集资金Z万元"
   输出: {"date":"","type":"I","exchange":"北交所/上交所/深交所","shares":数值,"price":数值,"total_raised":数值}

6. J型: 员工持股平台出资
   模式: "员工持股平台"+"增资/认购/出资"+"股份支付"
   ⚠️ 与A3的区别: J型是平台自身设立/出资, A3是公司向平台增发
   规则: "新设员工持股平台"+"出资" → J型
```

## 模块4: H型 — VIE提取 (仅当检测到VIE关键词时触发)

```
仅当原文含"VIE/红筹/协议控制/镜像回归/开曼岚锋"时触发。提取9个子事件:

H1 开曼岚锋设立: "设立开曼岚锋"
H2 香港岚锋设立: "开曼岚锋...设立...香港岚锋"
H3 北京WFOE设立: "香港岚锋...设立...外商独资"
H4 VIE协议签署: "协议控制...签署...控制协议"
H5 开曼岚锋回购: "开曼岚锋...回购"
H6 镜像回归: "镜像回归" OR "持股比例...保持不变" OR "等比例"
H7 VIE终止协议: "退出协议控制"
H8 股权出质注销: "出质注销"
H9 VIE实体注销: "已完成...注销"

⚠️ 假阳性过滤: "不存在VIE/无协议控制/不存在协议控制架构" → 跳过(H型不适用此公司)
```

## v3 相比 v2 的改进

| v2 | v3 |
|------|------|
| 只覆盖 A/E/F 三种类型 | 覆盖全部 10 种类型 |
| 混合在一个 prompt 中 | 分 4 个模块独立调用 |
| 无温度参数 | T=0.0 最大确定性 |
| A2/F陷阱在三协电机特化 | 陷阱规则通用化(适用所有公司) |
| 无 D 子类型优先级 | D1>D3>D2 显式优先级 |
| 无 VIE/IPO/吸收合并 | 模块3+4 全覆盖 |
| investor_type 未归一化 | 10 类标准标注 |
