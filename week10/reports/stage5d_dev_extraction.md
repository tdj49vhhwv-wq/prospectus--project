## 泛化点（方法为什么能跨板）

冻结的 Stage 7.2 parser 只认 STAR 板的「新增股份由 X 认购」HTML 认购表，而
主板/创业板/北交所的 PE/VC 入场结构完全不同，故 DEV 12 上 0 行。新的抽取器覆盖了：

1. **股权转让表** — 受让方列（rowspan 合并转让方单元格时的 first-non-numeric 回退）
2. **设立 / 整体变更 发起人表** — 股东名称列
3. **增资 prose** — "由 X、Y 分别以货币认缴 A 万元" / "向 X 定向发行"
4. **北交所特殊投资约定 prose** — "与 X、Y（简称投资方）签订…股权投资协议"

## 本轮 parser 修复（DEV 上 67.55% → 79.19%）

- **整体变更完成日**：股改「基准日」（审计基准）误作完成日 → 改取 换发营业执照 / 创立大会 / 工商登记日
  （301662 六行整体变更 2019-08 → 2020-05，全部转正）。
- **名字污染**：`_LEAD` 增 `新增注册资本`/`全部`；转让给 X 模式增 `用于` 终止符；
  定向发行模式加 `(?<!定)向` 负向后顾（避免「定向发行」自带的「向」误匹配）。
- **MinerU OCR 校正**：`尚顾祺能→尚颀祺能`、`捷泉/走泉元禾璞华→疌泉元禾璞华`
  （罕见字被 MinerU 在同文档内错成多个变体，归一化到正确形）。
