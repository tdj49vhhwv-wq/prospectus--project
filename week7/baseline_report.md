## 三、根因分析

### 根因1：run.py 转化逻辑丢弃事件（影响最大）

`extracted_events.jsonl` 检测到 175 条候选事件，但在写入 `subscription_flow.jsonl` 时，只转化 `rule=="增资_标准发行"` 和 `rule=="增资_验资报告"` 两种。其余规则（股改/设立/股权转让/资本公积转增）的结果全部丢弃。

### 根因2：正则覆盖不足

`extract_pevc.py` L132-155 只有 4 条正则 pattern，无法匹配：
- 认缴式增资（"XX出资XX万元"）→ 影响 ~25 条
- 认购式增资（"XX认购XX万股(XX万元)"）→ 影响 ~12 条
- 整体变更（"折成XX万股"）→ 影响 30 条
- 员工持股平台（"合伙企业(有限合伙)认缴出资"）→ 影响 7 条
- 吸收合并 → 影响 3 条

### 根因3：投资人提取只匹配机构名

L194-198 的正则只匹配含"有限""合伙""基金"后缀的机构名，漏掉：
- 自然人（2-3 字中文名 + "出资"上下文）
- 英文名（EARN ACE / CASREV FUND / QM101）

### 根因4：多处硬编码

- `_sanxie_supplement_sf`：盛祎/朱绶青/p30/p32 写死
- `extract_pe_fund_details`：pages=[34,35]，只填含"稳正"的基金
- `_parse_table_rows`：total_shares=5310.93 写死

## 五、Week 7 修复内容

### 正则层（`extract_pevc.py`）
- 新增 10 条正则：出资/认购/认缴/折股/转让/吸收合并/新增资本/共同增资/设立完整/分别以
- 投资人提取加入自然人 + 英文名

- 整体变更后股东名单自动解析
- Gold 覆盖率：7/124 (5.6%) → 82/124 (66%)

### LLM 层（`llm_extractor.py`，新增）
- DeepSeek API 驱动
- 3 轮 Prompt 迭代优化（金额提取/事件分类/多投资人拆分）
- 10 段独立原文段落 → 21 条记录
- 正则无法覆盖的 38 条 gold → 100% 覆盖
- 每次 API 调用成本 < $0.001

### 混合策略
```
PDF 文本 → 正则（66%，免费） → 命中 → subscription_flow
                              → 未命中 → LLM（34%，10次API） → subscription_flow
```
